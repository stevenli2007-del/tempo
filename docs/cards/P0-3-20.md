**实现（2026-09-18）**

- **同步侧零下载、零 LLM、1 个 SELECT**（`lib/sync/syllabus-drift.ts`，挂在 Pipeline **第 9 步**、排在资料索引之后）：从 3-19 的 `course_files` 里按 `pickSyllabusFile()` 挑出 syllabus 文件 → `decideDrift()` 比对锚点 → **变了才**建一条 `type='syllabus_drift'` 的消息（`driftStatus='pending'`）。**Canvas 请求 0 个、模型调用 0 次。**
- **三条「不」**（`lib/syllabus-drift/files.ts`，零依赖纯逻辑，同步侧 / 按需路径 / 回归脚本三处共用同一份判定）：**不下载**；**不猜**（`size_bytes === null` 不当候选）；**不诬告**（`modified_at === null` 时不报变更）。排序是**全序**（根目录 → PDF → 名字短 → 字典序 → id），刻意**不认 `outline`/`schedule`** —— 那是另一份文档，说它"变了"是诬告。
- **首次核对 / 换文件 = `baseline`（只记锚点，不提案）**：否则 6~13 门课首次同步会各塞一条纯噪音；换文件时两份文档没有共同锚点，「变了」在语义上不成立。
- **按需路径**（`lib/syllabus-drift/generate.ts` + `POST /api/v1/messages/drift`）：打开消息栏 → 客户端对 `needsDrift()` 的消息静默发一次请求 → 服务端下载**那一个**文件、抽文本、调模型 diff → 结果**写回消息的 payload**（原文/全文**绝不落库、不落盘、不进日志**，沿用 ADR-026 的三道闸门：扩展名/MIME → `size_bytes` 超限 → 缓存 `modified_at` 未变，**全在发请求前判**）。一轮最多 3 条、并发 2，`remaining > 0` 时客户端再来一轮（`MAX_DRIFT_ROUNDS = 2` 封顶）。
- **🔴 新写入的考试行必须 `source='syllabus'` + `is_confirmed=false`**（`lib/messages/appliers/syllabus-drift.ts`）：若写成 `is_confirmed=true`，下次老师改日期时界面会回「这条你已经确认过」→ **功能在第一次接受之后就死了**。写入后必须重跑 `syncExamToTask()`（ADR-004 派生的唯一实现）。
- **撤销与公告撤销有本质不同**（`lib/messages/undoers/syllabus-drift.ts`）：漂移里有 **update（改期）**，不能按 id 删，必须按 `applied.examRestores` 的**结构化旧值快照**写回去（界面那句人话 `before` 拆不回 `exam_date`/`exam_time`）。顺序 = 删新增考试 → 按快照还原更正 → 重跑 `syncExamToTask` → 删新增成绩构成。
- **低置信度不许一键接受**（卡面边界的落地）：扫描件 PDF 提取不准 → `confidence='low'` + `canAccept=false`，只能「知道了」。**已确认的行绝不自动覆盖**：applier 只照做 `change.writable`，**不重判**。
