#### 🎫 P0-3-30 · Canvas syllabus 自动发现与一键导入 ⚪

- **做什么**：老师在 Canvas Files 里放的那份 syllabus，Tempo 已经**能看见**（3-19 资料索引 + 3-20 的
  `pickSyllabusFile()` 挑用它当漂移锚点），但**从不解析它的内容** → 用户还是得自己再传一遍。
  本卡：课程页/消息栏提示「Canvas 上发现疑似 syllabus：\<文件名\>」→ **一键导入** → 复用 P0-1 的解析管线
  抽五板块 + 考试落库 → 同时把 3-20 的漂移锚点设为 `baseline`（不然下次同步会立刻报「大纲变了」）。
- **依赖**：P0-3-19 ✅（资料索引）、P0-3-20 ✅（锚点 + 按需下载范式）、P0-1-5 ✅（解析管线）。
- **必读**：[`../Decisions.md`](../Decisions.md) **ADR-026**（索引路径零下载 / 按需路径三道闸门 **全在发请求前**判）
  与 **ADR-015**（`source` 溯源不许污染）。
- **grep 范围**：`lib/syllabus-drift/**`、`lib/course-files/**`、`lib/parse/**`。

**关键约束**

1. 🔴 **必须走按需路径**（用户点了才下载 + 调模型）：**同步路径零下载**是 ADR-026 的红线，
   而且同步跑在 service role 下、模型审计写不进 `llm_runs`（ADR-003 / 3-20 已实测）。
2. 🔴 **原文不落库 / 不落盘 / 不进日志**；三道闸门顺序不变：扩展名与 MIME → `size_bytes` 超限 → 缓存 `modified_at` 未变。
3. 🔴 **已有用户手动上传 syllabus 的课程：不许静默覆盖**。明确显示「这门课已有一份你上传的版本」，
   让用户决定是要对比还是替换（走 3-24 的确认通道，ADR-015）。
4. 导入产生的考试行必须 `source='canvas'` + `is_confirmed=false`（同 3-20 的红线：写成 `true` 会让漂移第一次接受后就死）。
5. 落地后 `exam_dates → tasks` 只走 `syncExamToTask()`（ADR-004 唯一派生实现）。

**验收标准**

| # | 标准 |
|---|---|
| ① | Chem 1A 资料区发现 syllabus → 一键 → 五板块 + 考试进库，`source='canvas'`、考试 `is_confirmed=false` |
| ② | 重复点两次：第二次命中缓存、不重复插入（幂等） |
| ③ | 已有手动 syllabus 的课 → 先给提示，**任何一行都不被自动改** |
| ④ | 同步路径的 Canvas 请求数与同步耗时**不变**（证明没偷跑下载） |
| ⑤ | 导入后立刻跑一轮同步 → 不发漂移提案（锚点已 baseline） |
