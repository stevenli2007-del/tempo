#### 🎫 P0-3-30 · syllabus 两个来源：继续手动上传 **或** 从 Canvas 已抓取的文件里选 ⚪

- **做什么（Steven 2026-09-19 追加）**：「其实可以保留上传按钮，只不过同时允许用户直接在 Tempo 已经抓到的
  这些文件中直接选择一个作为 syllabus 上传即可。」
  所以本卡**不是替换** `components/courses/syllabus-upload.tsx`，而是**给它并排加第二个来源**：

  | 来源 | 入口 | 走的路径 |
  |---|---|---|
  | ① **上传文件**（保留，现有行为一字不改） | 原按钮，浏览器直传 Storage → `/api/v1/syllabi/:id/extract` → `/parse` | P0-1 既有管线 |
  | ② **从 Canvas 资料里选一份**（本卡新增） | 按钮旁的「从 Canvas 资料选一份」→ 列出这门课已索引的可抽文件 → 勾选 → 一键导入 | **按需路径**（ADR-026 第 2 条） |

  老师已经把 syllabus 传到 Canvas 上时，用户不必再找一遍本地文件；老师只发了纸质版 / 发在别处时，
  上传这条老路照旧在。**两条路的终点完全一致**：五板块 + 考试落库 → 肉眼同一份课程卡。

- **必读**：[`../Decisions.md`](../Decisions.md) **ADR-026**（尤其第 2/3/4 条：按需路径三道闸门**全在发请求前**判、
  Canvas 的 `url` 是**能力凭据**不可落库不可下发）与 **ADR-015**（`source` 溯源不许污染）。

**实现落点（已核过现有代码，按这个写）**

1. **下载与抽文本直接复用 3-19b**：`lib/course-files/summary/generate.ts` 已经把
   「单文件端点取新鲜 `url` → 下载字节（不落盘不入库）→ `lib/extract.ts` 抽文本」跑通了。
   本卡把这三步提出到一个零业务逻辑的 helper（暂名 `lib/course-files/fetch-content.ts`），
   **让「一键总结」与本卡共用同一份实现** ——
   两处各写一份的结果一定是「总结能读的文件、导入说不支持」。
2. **要不要建 `syllabi` 行：要，但不给它原文**。
   `syllabi` 表结构（`20260902003000_initial_schema.sql`）实测：`raw_text` **可空**、`file_url` / `file_name` **非空**。
   所以建行时：
   - `file_name` = Canvas `display_name`；
   - `file_url` = **站内路径** `/courses/{cid}/files/{fid}`（与资料区给用户的那条同构，走 `readInternalPath` 守卫）；
     🔴 **绝不能写 Canvas 单文件端点返回的 `url`** —— 那是能力凭据（ADR-026 第 3 条），写进去等于把永久钥匙落库；
   - `raw_text` **恒为 null**：全文只在内存里过一遍。
   因为 `handleParseRequest` 的先决条件是「`extract_status='extracted'` **且** `raw_text` 非空」，
   而本路径**刻意不写 `raw_text`**，所以 **不能**复用那个 handler —— 新建
   `importSyllabusFromCanvasFile()` 直接调 `parseSyllabusSections()` + `persistParsedSections()`（都在 `lib/parse/`），
   入参的 `rawText` 来自内存。除"不读库里的 raw_text"外，其余与 `handleParseRequest` 同构。
3. **幂等靠新增一列**，不靠猜：给 `syllabi` 加可空 `canvas_file_id uuid references course_files(id) on delete set null`
   + `unique (course_id, canvas_file_id)`（迁移由 Steven 手跑，SoT 在前）。
   第二次点同一个文件 → 命中已有行 → **一个外部请求都不发**。
   ⚠️ 不要用「这门课已经有 syllabi 行了吗」来判断：用户可能先手动传过一份（那时 `canvas_file_id is null`），
   那个 null 不参与 unique —— 这也是约束 3 要的场景。

**关键约束**

1. 🔴 **必须走按需路径**（用户点了才下载 + 调模型）：**同步路径零下载**是 ADR-026 的红线，
   而且同步跑在 service role 下、模型审计写不进 `llm_runs`（ADR-003 / 3-20 已实测）。
2. 🔴 **原文不落库 / 不落盘 / 不进日志**（含 `syllabi.raw_text` 与 `llm_runs` 的错误明细）；
   三道闸门顺序不变：扩展名与 MIME（`detectExtractableExtension`）→ `size_bytes` 已知且不超限 → 幂等缓存命中。
   **`size_bytes` 为 `null` 的文件不下载**（ADR-026 后果节：发请求前判不了成本就拒绝）。
3. 🔴 **已有 syllabus（手动上传的也算）的课程：不许静默覆盖**。明确显示「这门课已有一份 syllabus：\<文件名\>」，
   让用户决定对比还是替换（走 3-24 的确认通道，ADR-015）。
4. 导入产生的考试行必须 `source='syllabus'` + `is_confirmed=false`（3-20 迁移注释写死的理由：
   `source` 记的是**事实从哪来** —— 它来自一份 syllabus 文档，不是**它托管在 Canvas 上**；
   写成 `'canvas'` 会让漂移写入的旧考试被重解析漏掉）。
5. 落地后 `exam_dates → tasks` 只走 `syncExamToTask()`（ADR-004 唯一派生实现）。
6. 🔴 **成功导入后必须把 3-20 的漂移锚点设为 baseline**：`courses.syllabus_file_id = 该文件 id`、
   `syllabus_seen_modified_at = course_files.modified_at`；否则下一轮同步立刻报「大纲变了」。
7. 选文件的清单：**默认只列抽得动的**（`detectExtractableExtension` 认得），文件名含 `syllabus`/`大纲` 的排最前
   （评分规则直接复用 `pickSyllabusFile()` 的 `compareCandidates`）；抽不动的文件**灰掉 + 给原因**
   （`unsupportedReason`，必须是「Tempo 读不了」而不是「这份文件没内容」）。
8. 越权挡两次（同总结页）：RLS 查不到 → 404；查到了但 `file.course_id !== 路由里的 :id` → 404。
9. 失败二分法同 ADR-026 第 5 条：确定性失败（无文字层 / 超限 / 模型读不出）→ 明确报错且**不重试**；
   暂时性失败（Canvas 5xx / 网络 / 超时）→ 提示可重试，**不污染该文件的状态**。
