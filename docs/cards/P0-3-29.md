#### 🎫 P0-3-29 · 考试写入去重：改期语义 = **更新提案**，不是新增行 🔵 代码完成（2026-09-19，待 Steven 验收）

- **做什么（Steven 的原话：信息过量会忘记）**：老师在公告里说「Midterm 1 改期到 9/27」，Tempo 必须让用户**确认是不是改期**，而不是并列多出一条 `exam_dates`。
  现状是错 —— 🔴 **`lib/course-update/apply.ts:83-84` 的 `insertExams()` 只会 `insert()`，从不查已有行**：
  任何入口（对话框 / 3-25 公告）产出一条 exam，写入器就无条件插一行，
  于是 syllabus 里那条 `9/28` 与公告里那条 `9/27` **并存**，用户在界面上看不出哪条是真的。
  本卡在**共享写入器这一层**加「写之前先解析它落到哪一行」：命中已有考试 → 产出 `kind='update'` 提案；确无命中才新增。两条入口同时受益。

**关键约束**

1. 🔴 **匹配只在同课程内做**（跨课同名 exam 不许串），判据 = **考试名归一**：小写、去标点与空格、`Midterm1` ≡ `Midterm 1`。
   **绝不做语义别名推断**（不能自己得出 `Unit 1 Exam` ≡ `Midterm 1`）—— 猜错比不猜更糟。
2. 🔴 **多命中 = 不猜**。同课程有 2 条候选时沿用 3-8b 的「列出来让用户挑」，不许自动选第一条。
3. 🔴 **命中即 update 提案，绝不 insert**。提案必须显示 `before → after`（含时间）、来源摘录、置信度。
4. 🔴 **只有用户显式点「确认」才写**。同步 / 懒 diff / 任何自动路径都不得覆盖（ADR-015）。
   写的是 `exam_date` / `exam_time` / 摘录，**不动** `source` / `is_confirmed`（3-20 已定的溯源纪律）。
5. 🔴 **撤销必须按 `applied.examRestores` 的结构化旧值写回** —— 已存在的行不能按 id 删（会把用户原本那条也删掉）。
   与 3-20 同一套 undoer 语义，本卡复用它的写法。
6. **模型给的名字不可辨识**（如只写 "the exam"）→ 保守：标「疑似重复，请指定是哪一场」，**不许悄悄新增**。
7. 写完后必须重跑 `syncExamToTask()`（ADR-004 `exam_dates → tasks` 的**唯一**派生实现）。
