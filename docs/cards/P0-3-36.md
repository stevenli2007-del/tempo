# P0-3-36 · 考试「落到哪一条」由用户裁决 + Canvas 空壳作业去重

> 新开 2026-09-23。🔴 **这是 P0-3-13 freeze 前的第二个显式例外**（第一个是 `P0-3-35`）：
> 它不是新功能，是**数据准确性 bug** —— Tempo 自己往账里加了一场不存在的考试，
> 而用户只是点了一下「确认」。Steven 2026-09-22 拍板的那条界线仍然有效：
> **质量修复可以插队，新功能不行**。

---

## 1. 症状（Steven 2026-09-23 的两张截图）

1. **复习页出现 5 场考试，实际只有 4 场。**
2. **任务列表里同一场考试出现两次**：`Unit 1 Exam · 9/22`（syllabus 派生）
   与 `Unit 1 Exam · 日期待定 · 未提交`（另一条）。

## 2. 根因（真库溯源，不是推断）

### 2.1 多出来的第 5 场：座位公告的 create 提案

消息 `46d32653`「Chem 1A Exam 1 Locations」，payload 里白纸黑字：

```json
"examProposals": [{ "kind": "create", "examName": "Chem 1A exam",
                    "examDate": "2026-09-22", "candidates": [], "targetId": null }],
"receipt": "新增 1 条考试（Chem 1A exam · 2026-09-22）（该课现在共 5 条）"
```

链路：公告正文写「tomorrow night's **Chem 1A exam** (Sep 22)」→ 解析出考试名
→ `resolveExamTargets()` 按名归一比对库里的 `Unit 1 Exam`，**0 命中**
（`chem1aexam ≠ unit1exam`）→ 名字又不是纯通称（含 "Chem 1A"）→ **判 create**，
候选列表是空的 → 界面只给「确认」一个按钮 → 用户点了 → 插入 `exam_dates`
（`063f6a4a`，source=manual），派生出一条 task。

**P0-3-29 的纪律没有错，它只是没覆盖这种情形**：「多命中要让人挑」有了，
「0 命中却明显可能是同一场」没有。

### 2.2 任务列表重复：Canvas 上的空壳作业

真库：Chem 1A 有 4 条 `source=canvas` 的行 —— `Unit 1 Exam` / `Unit 2 Exam` /
`Unit 3 Exam` / `Final Exam`，**due_date 全为 null**。老师在 bCourses 建了
同名的壳（占位的作业条目，没填截止日），同步如实抓进来，于是与 syllabus 派生的
考试行**同名重复显示**。

---

## 3. 修法

### 3.1 判定：0 命中 + 同日已有考试 → 不许静默新增

`lib/course-update/exam-match.ts` 的 `resolveExamTargets()`：0 命中分支新增一条
——按**同课同日**找候选（排除本批已占位的行），命中就返回 `ambiguous`
（候选 = 那一天的行），回执写明「这门课 X 已有一场考试（Y），可能是同一场」。

🔴 **同日只命中 1 条也不自动 update**：同一天考两场（上午 quiz + 晚上 exam）是可能的，
自动覆盖的代价远大于让人点一下（与 P0-3-29「多命中不猜」同一条纪律）。
🔴 日期待定（`examDate === null`）无从按日比对 → 保持老行为（新增），不捏假候选。

### 3.2 写入：让用户挑「覆盖哪条 / 新增」

| 层 | 改动 |
|---|---|
| 判定状态 | `ensure.ts`：带候选的待裁决提案也算 `ready`（否则 applier 走「知道了」那条路 = 选了也不写） |
| 合并选择 | 新增 `lib/messages/exam-proposals/choose.ts` 的 `applyExamChoices()`（纯函数）：把用户挑的 id 写回 `payload.examProposals[].kind/targetId`，`null` = 强制新增 |
| 接口 | `PATCH /api/v1/messages/:id` 接受 `examChoices: [{ index, targetId }]`；**只认服务端那份 candidates 里的 id**（指名改任意行 = 绕过课程过滤），非法 → 400 |
| 界面 | `lib/messages/view.ts` 给 `MessageView.examChoiceGroups`（只给待处理的消息）；`messages-view.tsx` 画单选：每条候选「覆盖：…」+ 永远给「新增一条：…」；**没挑完就禁用确认**并说明 |

「新增一条」永远给 —— 用户看过候选仍然要新增是他的权利；没有这一项就成了系统逼人二选一。

### 3.3 空壳去重：只隐藏，不删数据

`lib/tasks.ts` 的 `dropCanvasExamPlaceholders()`（纯函数，唯一判据）：
**来源 canvas** + **没有截止日** + **标题归一命中同课某条考试任务** → 列表里不再显示。
应用到总览页（今日 / 周历 / 清单三处消费之前）与课程详情页。

🔴 必须带「没有截止日」这一条：老师一旦给那行填上日期，它就是真截止日
（Canvas 对 canvas 来源的行是权威），那时再隐藏就是丢数据。带上后**自愈**：
填了日期 → 条件不成立 → 这一行自己回来。

### 3.4 数据清理（Steven 2026-09-23 批准「删」）

删 `exam_dates` 的 `063f6a4a` + 它派生的 task `1b98d4d4`。三道闸：
① id + 课程 + 名字 + 日期四项核对；② `(course_id, exam_key='chem1aexam')` 下
**没有任何复习数据**（否则变孤儿，中止）；③ 删完复查该课剩 4 条。
结果：4 条（Unit 1 / Unit 2 / Unit 3 / Final，全 syllabus），复习文件 0、总结 0。

顺带把消息 `46d32653` 那句已经对不上账的回执补注
「（这行后来被确认为与 Unit 1 Exam 重复，已于 2026-09-23 清理）」——
`applied` 原样保留（撤销与对账的凭据）。

## 5. 验收

1. `npm run regress:course-updates` —— 0 命中同日 → ambiguous / 不同日照旧 create /
   显式新增压过候选 / 日期待定不捏候选（82 条全绿）。
2. `npm run regress:messages` —— 选择合并的四种路径 + 服务端只认候选内 id（121 条全绿）。
3. `npm run regress:progress` —— 空壳去掉 / 填了日期就回来 / 名字不同不误伤（42 条全绿）。
4. 真库复查：Chem 1A 考试 = 4 条；任务列表里 `Unit 1 Exam` 只剩有日期那一条。
5. 消息栏：造一条撞同日的公告（或直接看历史那条已清理的），确认按钮在挑之前**是灰的**。

---

## 6. 红线

- 🔴 **不许替用户猜**：同日命中 1 条也停下拉候选（自动覆盖 = 把 A 场的信息写到 B 场上）。
- 🔴 **服务端只认 candidates 里的 id**：客户端送的 targetId 必须在这份列表里。
- 🔴 **空壳判据只有一份**（`dropCanvasExamPlaceholders`），别处不得另写"名字像考试就隐藏"。
- 🔴 **不许删有复习数据的考试行**（会变孤儿），删前必须查 files / summaries 两张表。
