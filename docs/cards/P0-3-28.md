#### 🎫 P0-3-28 · 同步写入幂等（`numeric` 定标）🔵

- **做什么**：让「没有变化就不写库」这条铁律真正成立 —— 连跑两轮同步，第二轮必须
  `created 0 / updated 0 / deleted 0`。
- **依赖**：无。**必须排在 `P0-3-13`（freeze，出口门）之前** —— 带着"每轮都白写两次"
  进 freeze 不合适。

##### 症状与根因（在线探针实测，不是推理）

`scripts/probe-sync-idempotent.ts` 逐字段打印「库里的值 vs Canvas 给的值」：

| 行 | 列 | 库里 | Canvas | 结论 |
|---|---|---|---|---|
| Chem 1AL Lab 1 Prelab Quiz | `submission_score` | `9.92` | `9.923076923076923` | **噪音，永不收敛** |
| Chem 1AL Lab 3 Prelab Quiz | `submission_score` | `9.89` | `9.892857142857142` | **噪音，永不收敛** |
| Chem 1A Week 3 Discussion Quiz | `external_updated_at` | `22:00:03Z` | `23:00:05Z` | **真变化**（老师改过），写一次即收敛 |

根因：`points_possible` / `submission_score` 是 `numeric(10, 2)`（迁移 `20260917140000`），
而 Canvas 给的是未定标浮点；`hasChanged()` 直接比相等 → 判定永远为真 →
每轮 `updated 2`，`updated_at` 被无意义刷新，失去"这条数据什么时候真变过"的意义。

##### 修法：写入与比较**共用同一个已定标的值**

- `lib/numbers.ts` 新增 `roundToScale(value, scale = SCORE_SCALE)`（半值**远离零**，与
  Postgres `numeric` 一致；`null` 与 `0` 严格区分）；
- `lib/sync/canvas-tasks.ts` 新增 `toCanvasTaskFields()`：先定标，再同时用于**比较与写入**；
- `hasChanged()` 改为薄封装 `canvasTaskDiffs(...).length > 0` —— 逐字段差异与在线探针
  **共用同一份判定**（探针里再抄一遍判定，等于用另一份代码验这份代码）。

🔴 **只在比较端四舍五入是不够的**：那样落库的仍是未定标值，下一轮要靠"数据库的舍入规则
与 JS 一致"才收敛，而两者在边界值上并不一致（JS `Math.round(-2.5) = -2`，Postgres 给 `-3`）。
写入与比较共用同一个值 → **收敛由构造保证，不依赖任何舍入约定**。

##### 验收（实测）

- 纯断言 `npm run regress:sync`：真值定标、`null`/`0` 语义、定标幂等、真变化仍要写 —— 11 项全绿；
- 只读探针 `npm run probe:sync`：修复前 `需要写入的行 3`（2 噪音 + 1 真变化）→ **修复后 0**；
- 真账号连跑两轮 `--live`：5 门课 + 1 门空课**第二轮全部 `0/0/0`**
  （第一轮 Chem 1AL `created 1`、Chem 1A `updated 1`，都是真变化，写一次即停）。
