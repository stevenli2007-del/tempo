## 1. 三项范围（Steven 已拍板）

### ① 公告 PDF 附件里的考试地点解析

- 现状：`exam_dates.location` 两行皆 null —— Chem 1A「Exam 1 Locations」座位公告的地点在 **PDF 附件**里，附件内容从未进库（消息 `46d32653` 溯源结论）。
- 做法：公告带 PDF 附件时，按需路径拉取附件 → 抽文本（`unpdf` 四条硬约束见 `TechStack.md` §2）→ 解析地点 → 提案进消息栏 → 确认后写 `exam_dates.location`。
- 🔴 **ADR-026**：按需读取那一个文件，原文不落库 / 不落盘 / 不进日志；同步路径零下载。
- 懒生成范式（ADR-024）：不进同步路径，打开消息栏后触发，失败落 `failed` 不重试。

### ② 作业改期从公告路径走通

- 现状：公告解析出改期意图时只回「请用对话框确认」（P0-3-36 卡面 §4 已记档）；且 Canvas 来源的行直接写会被下一轮同步改回去。
- 做法：公告提案支持对**手动 / exam 来源**行的 due date 更新提案（复用 3-29 的 `resolveExamTargets()` + `applied` 旧值快照 + 撤销写回旧值）；**canvas 来源的行不写 due date**（写回去必被同步抹掉——要么提示去 Canvas 改，要么提案文案如实说明）。
- 🔴 改期 = **更新那一行**（按考试名归一命中），绝不并列新增（3-29 红线）；0 命中同日 = ambiguous 让人挑（3-36 红线）。

### ③ 提醒邮件列表过空壳过滤

- 现状：提醒邮件（P0-3-14）的任务列表没过 `dropCanvasExamPlaceholders()`，Canvas 空壳占位行会进邮件。
- 做法：邮件组装处调用同一份过滤函数（**唯一判据**，不得另写「名字像考试就隐藏」）。

## 6. 实现记录（2026-10-04，Steven 开工 + 两项拍板）

Steven 拍板：**① 附件走零迁移方案**、**② Canvas 行"出提案但标不可写"**。三项全部落地，零迁移。

### ③ 提醒邮件过滤空壳（最简单，先做）

- 原先这两层筛选散在 `engine.ts`（异步 IO 层，回归脚本 import 不了）。抽成
  **`lib/reminders/select.ts`** 的 `selectReminderTasks()` —— 现在「邮件里列了什么」能被
  `regress:reminders` 直接钉死（原先只能真发一封邮件才看得见，而它错了是静默的）。
- 🔴 **顺序 = 先去空壳、再判可提醒**：`dropCanvasExamPlaceholders` 要在**全量**上跑，
  它靠"同课有没有这场考试"建键；先过 `isRemindable` 会把已完成的考试行滤掉 → 键变少 →
  对应的空壳行漏出来，那条计数就对不上账。回归里有专门的断言守这个顺序。
- 判据仍只有那两份（空壳 = `dropCanvasExamPlaceholders`、可提醒 = `isRemindable`），
  **没有第三套**。

### ② 作业改期从公告走通

- 新增纯模块 **`lib/course-update/task-match.ts`**（与 `exam-match.ts` 同构）：
  `canEditTask()` / `resolveTaskTargets()` / 七种 `kind`。
- 🔴 **可写判据只有一条**：`manual + 非派生`。它原先只活在客户端组件里
  （`use-course-update-flow.ts` 的 `isEditable`），收到 lib 之后两端同一份 ——
  否则会出现"界面说能改、公告说写不了"，用户不知道该信谁。
- **只做改期、不做新增**：0 命中 = `unmatched`，不凭一条公告新建作业
  （公告是无人编辑的通道，凭空建作业比"没写"危险；而"没写"会被回执如实说出来）。
- **命中但写不了 ≠ 没匹配到**：`blocked_canvas` / `blocked_derived` 照样出提案并说明原因
  （Steven 拍板）。两者在界面上都"不写"，但给用户的行动完全不同。
- 写入走 `.eq('source','manual')` 收口（tasks 有两个写入方，漏了它就会改 Canvas 的行、
  而下一轮同步又改回去 —— 表现为"改了没生效"且零报错）；撤销**按旧值写回**（不按 id 删）。
- `applied.taskRestores` 进了 `countApplied()` —— 漏了它用户会看到「✓ 已确认」却找不到撤销按钮。

### ① 公告 PDF 附件里的考试地点

- **零迁移**：附件清单**不落库**。懒补时现场打单条公告端点
  `GET /api/v1/courses/:cid/discussion_topics/:id` 拿附件（批量端点的窗口是"当天+昨天"，
  几天后才打开消息栏时它早已取不到那条公告），下载 → `unpdf` 抽文本 → 解析 →
  **原文只在内存里过一遍**（ADR-026）。`attachment.url` 是能力凭据，不落库不下发。
- **触发条件收得很紧**：只有「解析出了考试、但它没带地点」时才读附件。
  每条公告都下 PDF 会同时烧 Canvas 限流、模型与用户等待时间。
- 附件**单独解析**（`purpose='announcement_attachment'`），不并入正文 ——
  混在一起会让 `sourceExcerpt`（逐字原文摘录）指不清出处，而摘录是用户核对"凭什么这么写"的
  唯一凭据，指错出处比没有更糟。
- 附件抽出的考试**追加**在正文那批之后：同一场会被"批内占位"挡成 `duplicate`（不连写两次）。
